# Requirements Document

## Introduction

Integrate VNPAY payment gateway into the online learning platform to enable secure payment processing for course purchases. The integration will handle payment initiation, real-time status updates, and payment result handling through the order-service microservice.

## Glossary

- **VNPAY_Gateway**: The VNPAY payment gateway service that processes payment transactions
- **Order_Service**: The microservice responsible for managing orders and payments in the system
- **Payment_Transaction**: A financial transaction between a user and the platform through VNPAY
- **Payment_URL**: A secure URL generated by VNPAY for payment processing
- **Secure_Hash**: Cryptographic signature generated using HMAC SHA512 to verify transaction integrity
- **IPN_Listener**: Instant Payment Notification listener that receives payment status updates from VNPAY
- **Return_URL**: URL where users are redirected after payment completion
- **QR_Code**: Quick Response code displayed for mobile payment scanning
- **Transaction_Reference**: Unique identifier for each payment transaction (vnp_TxnRef)
- **NCB_Test_Card**: Test card for sandbox environment with number 9704198526191432198
- **Test_OTP**: One-time password "123456" for test card authentication

## Requirements

### Requirement 1: Payment URL Generation with VNPAY Configuration

**User Story:** As a student, I want to initiate a payment for course purchase, so that I can securely pay for courses using VNPAY.

#### Acceptance Criteria

1. WHEN a user requests payment for an order with valid parameters, THE Order_Service SHALL generate a Payment_URL with required VNPAY parameters
2. THE Payment_URL SHALL include vnp_TmnCode="10X00MH4", vnp_Amount, vnp_TxnRef, vnp_OrderInfo, vnp_ReturnUrl
3. THE Order_Service SHALL calculate vnp_SecureHash using HMAC SHA512 with secret key "YGNAXUG77ENYIIQCL7TIDS10SIMOYLGE"
4. WHERE vnp_Url is "https://sandbox.vnpayment.vn/paymentv2/vpcpay.html", THE Payment_URL SHALL redirect to VNPAY sandbox
5. IF parameter validation fails, THEN THE Order_Service SHALL return an error with specific validation details

### Requirement 2: Payment Status Processing with Guaranteed Access Grant

**User Story:** As a student, I want my course access granted immediately when payment succeeds, so that I can start learning without delay.

#### Acceptance Criteria

1. WHEN VNPAY sends an IPN callback, THE Order_Service SHALL validate the vnp_SecureHash
2. WHEN vnp_SecureHash validation succeeds, THE Order_Service SHALL update the order status based on vnp_ResponseCode
3. WHERE vnp_ResponseCode="00" (success), THE Order_Service SHALL grant course access to the user
4. WHERE vnp_SecureHash validation succeeds AND vnp_ResponseCode="00", THE Access_Grant SHALL occur regardless of whether the payment status changed from a previous state
5. IF IPN validation fails, THEN THE Order_Service SHALL log the error and ignore the callback

### Requirement 3: Real-time Payment Status Updates

**User Story:** As a student, I want to see real-time payment status updates, so that I know when my payment is confirmed without refreshing the page.

#### Acceptance Criteria

1. WHILE payment is pending, THE Order_Service SHALL provide status updates through WebSocket or polling
2. THE Frontend SHALL display loading spinner and countdown timer during payment processing
3. WHEN payment status is confirmed, THE Frontend SHALL update UI immediately without page refresh
4. IF WebSocket connection fails, THEN THE Frontend SHALL fallback to polling every 5 seconds
5. THE Real-time_Updates SHALL continue until payment completes or times out

### Requirement 4: Professional Payment UX/UI

**User Story:** As a user, I want a professional payment interface with VNPAY branding, so that I feel confident in the payment process.

#### Acceptance Criteria

1. THE Payment_Page SHALL display official VNPAY logo and branding elements
2. WHERE QR code payment is available, THE Frontend SHALL display QR code with clear instructions
3. THE UI SHALL include loading spinner during payment processing
4. THE Countdown_Timer SHALL display remaining time for QR code validity (15 minutes) until expiration
5. IF UI resources fail to load, THEN THE Frontend SHALL display graceful fallback with payment instructions

### Requirement 5: Payment Result Page Handling

**User Story:** As a student, I want to see clear payment results with appropriate actions, so that I can proceed to my course or retry payment if needed.

#### Acceptance Criteria

1. WHEN a user returns from VNPAY payment, THE Frontend SHALL display appropriate result page based on vnp_ResponseCode
2. WHERE vnp_ResponseCode="00", THE Success_Page SHALL show transaction details and "Start Learning" button
3. WHERE vnp_ResponseCode≠"00", THE Failure_Page SHALL show error reason and "Retry Payment" button
4. THE Result_Page SHALL display vnp_TransactionNo, vnp_Amount, vnp_OrderInfo, and vnp_PayDate
5. IF Return_URL validation fails, THEN THE Frontend SHALL process payment result first, then redirect to generic error page

### Requirement 6: Test Card Support for Development

**User Story:** As a developer, I want to test payment flows with test cards, so that I can verify integration without real money.

#### Acceptance Criteria

1. WHERE environment is "sandbox", THE System SHALL accept test card "9704198526191432198" that passes standard validation rules
2. WHEN test card is used, THE VNPAY_Gateway SHALL simulate successful payment with OTP "123456"
3. THE Test_Flow SHALL bypass real bank transactions while maintaining full integration logic
4. THE Test_Card SHALL be associated with cardholder name "NGUYEN VAN A" and expiry "07/15"
5. IF test card validation fails, THEN THE System SHALL provide specific error message for developers

### Requirement 7: Payment Configuration Management

**User Story:** As a system administrator, I want to manage VNPAY configuration securely, so that payment gateway settings can be updated without code changes.

#### Acceptance Criteria

1. THE Order_Service SHALL load vnp_TmnCode, vnp_HashSecret, and vnp_Url from environment variables
2. WHERE environment variables are missing, THE Order_Service SHALL use default sandbox values provided in requirements
3. THE Configuration SHALL support switching between sandbox and production environments
4. IF configuration validation fails during startup, THEN THE Order_Service SHALL log warning and use safe defaults

### Requirement 8: Payment Status Synchronization Across Services

**User Story:** As a user, I want my payment status synchronized across all services, so that course access is immediately available after payment.

#### Acceptance Criteria

1. WHEN payment succeeds, THE Order_Service SHALL publish "payment.completed" event
2. THE Course_Service SHALL listen to "payment.completed" events and grant course access
3. THE Notification_Service SHALL send payment confirmation email on "payment.completed"
4. IF event propagation fails, THEN THE Order_Service SHALL retry with exponential backoff after confirming downstream services missed the event
5. WHERE eventual consistency is acceptable, THE System SHALL tolerate up to 5 seconds delay

### Requirement 9: Error Handling and Retry Logic

**User Story:** As a user, I want robust error handling for payment failures, so that temporary issues don't block my course purchase.

#### Acceptance Criteria

1. WHEN VNPAY API call fails, THE Order_Service SHALL retry up to 3 times with 1-second intervals
2. IF all retries fail, THEN THE Order_Service SHALL return user-friendly error message
3. WHERE multiple consecutive network timeouts occur, THE Order_Service SHALL implement circuit breaker pattern
4. THE Error_Handling SHALL distinguish between temporary failures and permanent errors
5. IF database connection fails during IPN processing, THEN THE Order_Service SHALL queue for later processing

### Requirement 10: Security and Compliance

**User Story:** As a security officer, I want secure payment processing that complies with PCI DSS requirements, so that user payment data is protected.

#### Acceptance Criteria

1. THE vnp_HashSecret SHALL never be logged or exposed in client-side code
2. ALL API calls to VNPAY SHALL use HTTPS with certificate validation
3. THE Order_Service SHALL validate all input parameters for type, range, and format
4. WHERE sensitive data is stored, THE System SHALL encrypt it at rest
5. IF security validation fails, THEN THE Order_Service SHALL reject the transaction and alert administrators
